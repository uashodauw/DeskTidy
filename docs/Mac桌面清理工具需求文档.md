# Mac 桌面清理工具 需求文档（v0.2 草稿）

> 产品名：未定，暂用"Mac 桌面清理工具"。

---

## 1. 一句话定位

让同时开着一堆 AI 工具干活的人，一键收起眼前不需要的东西，屏幕立刻清爽，切换不再掉帧。

宣传语（备选）：多开 AI 不卡顿，一键找回清爽的 Mac。

---

## 2. 要解决的问题

做 vibecoding 或用 AI 工具干活时，必须同时开多个 agent 软件、AI 网页和沟通工具，结果是：

| 痛点 | 描述 | 优先级 |
|---|---|---|
| 电脑卡 | 切换窗口时明显掉帧（M5 / 16GB 内存的机器上也会出现） | **最高** |
| 看着烦 | 窗口堆满屏幕，视觉上乱 | 高（决定第一眼体验） |
| 找不到 | 偶尔要用的应用（典型如飞书）被埋住，只能三指上划后慢慢找 | 中 |
| 怕被看到 | 共享屏幕或别人路过时，不想暴露某些窗口 | 中 |

现状：用调度中心（三指上划）手动翻找，"勉强能忍"。

推论：痛感不算剧烈，所以产品必须几乎零成本就能用，否则用户宁愿继续忍。

---

## 3. 目标用户

**第一版的设计标准：** 用 AI 工具干活、但不太写代码的人，例如**产品经理、设计师**。默认设置、默认场景都以他们为准。

用户特征：
- 会同时开多个 AI 工具（agent 软件、ChatGPT、AI 网页等）。
- **不关心原理，只看结果**：不需要懂活动监视器、内存、进程这些概念。
- 电脑配置不一定低：问题来自多开 AI 工具，不只是老机器才有。

**第一个体验者：** 作者本人（做 vibecoding）。作者先用，但产品按产品经理、设计师的习惯设计。

---

## 4. 核心使用场景

**场景：多开 AI 工具干活，屏幕变乱、切换开始掉帧的时候。**

1. 用户同时开着当前工作场景需要的应用（如 AI 工具、沟通工具、浏览器里的 AI 网页），以及其他零散窗口。
2. 切换窗口开始掉帧，屏幕上堆满窗口，要用的东西找不到。
3. 用户**主动**触发"一键清理"。
4. **立刻得到明显的反馈：** 屏幕上只剩当前场景要用的东西，并且用户能明显感知到"清理生效了"（反馈形式待确认，见 Q2）。
5. **持续感受到的结果：** 之后切换窗口更流畅。
6. 需要被收起的应用时，能快速把它找回来；也可以一键恢复到清理前的样子。

**附属场景：**
- **共享屏幕前**：一键藏好不想被看到的窗口。
- **找飞书这类偶尔用的应用**：不用再三指上划慢慢找。

**目标使用频率：** 每天都用。付费理由是"用习惯了，离开它多开就卡"。

## 5. 核心功能点（本版）

| # | 功能 | 说明 | 状态 |
|---|---|---|---|
| F1 | 一键清理 | 用户主动触发，让屏幕只剩当前场景需要的东西 | 确定 |
| F2 | 即时高反馈 | 清理后用户必须马上明显感知到效果；只靠"之后慢慢变顺"不够 | 确定要有；形式待确认（Q2） |
| F3 | 场景与受保护应用 | 不同工作场景有不同的"不能动"的应用。内置若干高频默认场景，用户可以自己设定每个场景包含哪些应用 | 确定；默认场景待确认（Q1） |
| F4 | 绝不关闭主要应用 | 当前场景里的主要应用绝对不会被直接关掉 | 确定；非主要应用如何处理待确认（Q3） |
| F5 | 清理范围 | 以下三类都算"多余"：不在受保护范围内的应用、不是当前正在用的应用、一段时间没碰过的应用 | 确定；三者冲突时的优先级待确认（Q4） |
| F6 | 一键恢复 | 清理后可以一键恢复到清理前的样子 | 确定 |
| F7 | 快速找回常用应用 | 飞书这类偶尔用的应用，可以快速叫出来 | 确定 |
| F8 | 共享屏幕隐私 | 共享屏幕前一键藏好不想被看到的窗口 | 确定 |
| F9 | 多种触发方式 | 支持多种主动触发方式 | 确定；具体方式在设计阶段决定 |
| F10 | 用户自设的定时清理 | 只有用户主动设定后才会定时执行 | 是否放进本版待确认（Q6） |
| F11 | 减轻卡顿 | 清理后切换窗口更流畅 | 确定要有 |
| F12 | 零理解成本 | 用户不需要懂任何技术概念，点了就有结果 | 确定 |

### 硬性原则

1. **绝不自动清理。** 清理必须由用户主动触发；唯一例外是用户自己设定的定时清理。
2. **绝不直接关掉用户的主要应用。**
3. **必须有明显的即时反馈。** 清理后效果不明显，就算这一版不成功。

## 6. 这一版先不做

以下内容在讨论中出现过，但**不在作者明确提出的本版范围内**。

- 趣味功能：桌面宠物、成就徽章、每周报告等。（清理动画、音效是否作为"即时反馈"的一部分，见 Q2）
- 老板键（一键切换到"认真工作"的界面）。
- 专注倒计时 / 番茄钟。
- 浏览器标签页级别的管理（单独关闭某些标签页）。
- 技术向的信息展示：进程列表、内存图表等（用户只看结果）。
- 任何形式的自动清理（用户自设的定时清理除外）。
- 付费、账号、授权体系（作者先体验阶段不需要）。
- Mac 以外的平台。

## 7. 待确认问题（第二轮）

**Q1. 默认场景有哪些？**
需要内置一些高频场景，并且以产品经理、设计师为准。具体是哪几个场景，每个场景默认保护哪些应用？例如"写需求文档""做设计稿""开会"……你是否有渠道问到真实的产品经理、设计师？

**Q2. "明显的即时高反馈"是什么形式？（与之前的回答有张力）**
你之前选了"主观感受变顺"作为结果，没有选"看到一个数字"。但现在要求清理后必须有明显的即时反馈，而"变顺"需要用一会儿才能感受到。即时反馈可以是：
- 屏幕瞬间变干净（视觉）
- 清理动画、音效（感官）
- 一个结果数字，例如"释放了 3.2GB 内存"、"收起了 12 个窗口"（数据）

你接受哪些？显示数字是否和"用户不需要懂技术"冲突？

**Q3. 非主要应用怎么处理？**
"绝对不能直接关掉主要应用"，那么非主要应用呢？
- 只隐藏，不退出？
- 可以直接退出？
- 退出前要先问用户？

另外，"主要应用"是否就等于"当前场景里的受保护应用"？

**Q4. 三种"多余"冲突时听谁的？**
例如：
- 某个受保护应用已经很久没碰了，要清理吗？
- 当前正在用的应用不在受保护范围内，要清理吗？

**Q5. 第一版范围是否过大？**
本版目前包含：一键清理、即时反馈、场景、恢复、快速找回、共享屏幕隐私、多种触发方式，可能还有定时清理。如果要先做出一个能每天用的版本，请给这些功能排个优先级，或者确认全部都要。

## 8. 已确认的决定（第一轮）

| 问题 | 决定 |
|---|---|
| 作者列出的 IDE、ChatGPT、飞书、浏览器上的 AI 网页 | 属于"不能动"的应用，但不只这些，按具体场景分析 |
| 屏幕干净了但卡顿改善很小，算不算成功 | 不算。必须有用户明显的即时高反馈 |
| 谁来决定退出哪个应用 | 内置若干高频场景作为默认设置，用户可以自己设定场景里的应用；绝对不能直接关掉用户的主要应用 |
| 什么算"多余" | 不受保护的、不是当前在用的、一段时间没碰的，都算 |
| 第一版做给谁 | 以产品经理、设计师为标准，作者先体验 |
| 一键恢复、快速找回常用应用、共享屏幕隐私 | 都放进本版 |
| 怎么触发清理 | 可以有多种方式，但必须完全由用户主动触发；绝不自动清理，除非用户自己设定定时清理 |
